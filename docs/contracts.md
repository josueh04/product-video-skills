# Contracts

The files, formats and command lines every skill and script agrees on. If you change one, change
every skill that reads it in the same pull request, and keep `tests/run.sh` green.

## 1. The workbench

```
product-video-skills/            # the workbench (this repo), called PVS_HOME below
  setup.sh                       # installs everything; /video-setup runs it
  package.json                   # pins hyperframes (exact version, no caret)
  requirements.txt               # Python deps for .venv
  bin/pvs-py                     # runs .venv/bin/python with lib/ on PYTHONPATH
  lib/pvs.py                     # shared helpers: find the workbench, load product.yaml, paths
  skills/<name>/                 # SKILL.md, scripts/, references/, assets/, evals/evals.json
  _template/product/             # copied by /product-new
  _template/video/               # copied by /video-new
  examples/acme/                 # a fictional product used by setup and tests
  products/<slug>/               # your products, gitignored here, each with its own git
  vendor/hyperframes/            # sparse clone of heygen-com/hyperframes at the pinned tag (gitignored)
  .claude/settings.json          # permissions and hooks for the workbench
  .claude/hooks/                 # session-start.sh, guard.sh
  .claude/skills/                # symlinks to skills/* and vendor/hyperframes/skills/* (made by scripts/link-skills.sh)
  tests/run.sh                   # self-check, prints "passed N, failed 0"
```

Every product folder also gets `.claude/skills/` symlinks and a copy of the settings, so
`cd products/<slug> && claude` sees the same skills.

### Calling a script from a skill

Skills resolve the workbench from their own real path, so they work from the workbench and from a
product folder:

```bash
PVS_HOME="$(cd "$(cd "${CLAUDE_SKILL_DIR}" && pwd -P)/../.." && pwd)"
"$PVS_HOME/bin/pvs-py" "$PVS_HOME/skills/<name>/scripts/<script>.py" ...
```

The session-start hook also writes `PVS_HOME` into `CLAUDE_ENV_FILE` when Claude Code provides it.
Scripts never rely on the current directory to find the workbench: they call `pvs.workbench()`.

Python is 3.9 or newer. No syntax newer than 3.9 (no `match`, no `X | Y` types at runtime).

## 2. A product

```
products/<slug>/
  product.yaml                   # the single source of product config (schema below)
  CLAUDE.md                      # generated by /product-new; points to the workbench rules
  .claude/                       # skill links and settings
  .gitignore                     # sources/, *.mp4, renders/, qa/sheets, qa/strips, audio/raw
  kit/
    RULES.md                     # the product's video rules (from _template/product/RULES.md)
    tokens.css                   # design tokens as CSS custom properties, each with a citation comment
    fonts/                       # woff2 files, fonts.css and fonts.md (source and license)
    icons/                       # SVG subsets, one file per icon, plus icons.md (name, source citation)
    logos/                       # light, dark and app-tile variants, plus logos.md (source of each)
    render-facts.md              # measured facts the composer needs (canvas, rem, scrollbars, fonts in use)
  sources/<role>/                # read-only export of each source at its pinned commit (never edited)
  sources/.git-cache/            # shallow clones of URL sources, reused on refresh
  sources.lock                   # JSON, see below
  references/<name>/             # recordings, frames, OCR timelines, captures
  videos/<video>/                # one per video, see section 3
  deliveries/                    # delivered MP4s and their BRIEF copies
```

### product.yaml

```yaml
product:
  name: Acme Tasks
  slug: acme
  positioning: "Acme Tasks is the to-do list that plans your day."
  never_say: ["the last app you will ever need"]
  names:                         # canonical name -> legacy strings that must not appear on screen or in narration
    Acme Tasks: ["AcmeTodo"]
  pronounce:                     # what the TTS receives instead of the canonical spelling
    Acme: AK-mee                 # or {say: AK-mee, vowel: ae, confusable: ey} to add a first-vowel check
  banned_terms: []               # anything that must never be seen or heard (competitors, vendors, real customers)
sources:                         # zero or more; role is a short id used as the folder name in sources/
  - role: frontend
    url: https://github.com/example/acme-web.git   # or: path: ../acme-web
    branch: main                 # the branch that is in production
    app_dir: src                 # where the UI code lives inside the repo
    framework: react             # angular-primeng | react | vue | svelte | html | other
  - role: backend
    path: ../acme-api
    branch: main
docs: []                         # URLs, repo paths or "mcp:<name>" (read-only)
app_canvas:
  logical: [1440, 810]           # the app viewport the UI is rebuilt at, scaled to 1920x1080
  theme: light                   # light | dark
  rem_px: 16
brand:
  accent: "#4F46E5"
  font: Inter
  logo_light: kit/logos/logo-light.svg
  logo_dark: kit/logos/logo-dark.svg
  app_tile: kit/logos/app-tile.svg
cast:                            # fictional only: names, 555 phone numbers, emails on example.com/.test domains
  company: {name: Northwind Bakery, city: Portland OR}
  people:
    - {role: owner, name: Maya Lindqvist, email: maya@northwind.example}
    - {role: customer, name: Omar Haddad, phone: "+1 503 555 0172"}
voice:
  provider: elevenlabs           # elevenlabs | say (macOS, free, for tests and drafts)
  env_key: ELEVENLABS_API_KEY    # read from PVS_HOME/.env by tts.py, never printed
  roles:                         # the role column of lines.tsv points here
    narrator: {voice: "<elevenlabs voice id>", model: eleven_multilingual_v2, say_voice: Samantha}
    # optional per role: settings (provider voice settings), context, say_rate, treatment: phone|room
  clip_lufs: -18
  mix_lufs: -16
video:
  size: [1920, 1080]
  fps: 30
  max_zoom: 1.35
  lang: en
review:
  reviewer: ""                   # who signs coverage and claims
  report_language: en
  naming: "{product} {video} v{version}.mp4"
```

`lib/pvs.py` loads it with defaults for every missing key, so an old product.yaml keeps working.

### sources.lock

```json
{
  "frontend": {"url": "https://...", "branch": "main", "commit": "<sha>", "fetched_at": "2026-01-01T00:00:00Z", "app_dir": "src"},
  "backend":  {"path": "../acme-api", "branch": "main", "commit": "<sha>", "fetched_at": "..."},
  "design":   {"path": "../not-a-repo", "tree_sha256": "<hash>", "fetched_at": "...", "pinned": false}
}
```

A URL is shallow-cloned at the branch. A local git path is exported with `git archive` at the
branch head (the working tree is never touched). A local path that is not a git repo is copied
and pinned by a hash of its files, with `"pinned": false`. Citations use
`<role>/<path>:<line>@<short sha>`. A local git source also records the resolved `ref`. A non-git
source is cited with `@` plus the first 7 characters of its `tree_sha256`.

## 3. A video

```
videos/<video>/
  BRIEF.md                       # frontmatter below, then intent, audience, chapters, notes, changelog
  COVERAGE.md                    # feature coverage matrix: feature | must explain on screen? | chapter | proof
  CLAIMS.md                      # positioning, phrases to avoid, claims needing approval, answers
  SOURCES.md                     # source-recon output: screen | route | components | citation
  TRUTH.md                       # product-truth output: id | sentence | source | visibility | verdict | notes
                                 # visibility: ui | backend | docs | mock
                                 # verdict: backed | approved | needs-approval | rewrite | cut | unbacked | mock
  specs/<screen>.md              # ui-spec-from-code output, with specs/<screen>.html snippets
  audio/
    lines.tsv                    # header "id	role	speed	text"; lines starting with # are comments
    raw/                         # provider takes, untouched (gitignored): <id>.mp3|.aiff, <id>.json,
                                 # prev/ (the take before, for --restore), cache.json (skip unchanged lines)
    clips/<id>.wav               # 48 kHz mono, trimmed, normalized to voice.clip_lufs
    timings.json                 # {"<id>": {"dur": 6.41, "words": [{"w": "Acme", "s": 0.36, "e": 0.84, "say": "AK-mee"}]}}
                                 # w is the on-screen spelling; say (optional) is what the TTS received
    sfx.tsv                      # optional: sounds make_sfx.py prebuilds
    sfx/                         # sfx used by the build, with sfx/CREDITS.md
  video/
    build.py                     # beats derived from timings.json; writes index.html
    src/template.tpl             # HTML with {{PLACEHOLDERS}}
    src/app.css                  # the product UI rebuilt from specs
    assets/                      # images, fonts and icons copied from kit/
    package.json                 # pins hyperframes like the workbench
    hyperframes.json
    index.html                   # generated, never edited by hand
    renders/<video>-v<k>.mp4
  qa/
    REPORT.json                  # see below
    REPORT.md
    sheets/  strips/  parity/
```

### BRIEF.md frontmatter

```yaml
---
title: Acme Tasks in 60 seconds
video: pitch
format: pitch                    # pitch | tour | docs | tutorial | loop
duration_s: 60
lang: en
reviewer: ""
version: 1
coverage_signed_by: ""           # set by the reviewer (their name) after reading COVERAGE.md
claims_signed_by: ""             # set by the reviewer after reading CLAIMS.md
---
```

`build.py` refuses to build while either signature is empty, unless it is run with `--draft`
(draft builds can be rendered and checked, never delivered).

### qa/REPORT.json

```json
{
  "mp4": "video/renders/pitch-v1.mp4",
  "sha256": "<sha256 of the mp4>",
  "created": "2026-01-01T00:00:00Z",
  "draft": false,
  "checks": [{"name": "black_frames", "passed": true, "detail": "0 found"}],
  "passed": true
}
```

`deliver.py` refuses an MP4 unless `REPORT.json` exists, says `"passed": true`, says
`"draft": false` and its `sha256` matches the file.

## 4. Command lines

| Script | Command |
|---|---|
| fetch sources | `bin/pvs-py skills/source-recon/scripts/fetch_sources.py <product_dir> [--refresh]` |
| changed since lock | `bin/pvs-py skills/source-recon/scripts/changed_since.py <product_dir>` |
| new product | `bin/pvs-py skills/product-new/scripts/new_product.py <slug> [--from examples/acme] [--answers FILE] [--dest DIR]` |
| new video | `bin/pvs-py skills/video-new/scripts/new_video.py <product_dir> <video> --format pitch` |
| sign brief | `bin/pvs-py skills/video-new/scripts/sign.py <video_dir> ...` (see its `--help`) |
| stage status | `bin/pvs-py skills/video-build/scripts/stages.py <video_dir> [--require STAGE] [--json]` |
| feedback table | `bin/pvs-py skills/video-review/scripts/feedback_table.py ...` |
| bump version | `bin/pvs-py skills/video-review/scripts/bump_version.py <video_dir>` |
| voice | `bin/pvs-py skills/script-and-voice/scripts/tts.py <video_dir> [--only N1,N3] [--provider say]` |
| sfx | `bin/pvs-py skills/script-and-voice/scripts/make_sfx.py <video_dir>` |
| build | `bin/pvs-py <video_dir>/video/build.py [--draft]` |
| motion lint | `bin/pvs-py skills/seek-safe-motion/scripts/lint_motion.py <video_dir>/video` |
| QA | `bin/pvs-py skills/render-qa/scripts/qa.py <video_dir> <mp4>` |
| deliver | `bin/pvs-py skills/render-qa/scripts/deliver.py <video_dir> <mp4>` |
| status | `bin/pvs-py skills/video-ask/scripts/status.py [<dir>]` |

Every script prints a short human summary, exits non-zero on failure, and never prints a secret.
